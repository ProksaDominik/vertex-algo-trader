# Instructions for AI assistants (Claude, ChatGPT/Codex, …)

This repo is **Vertex Algo Bot** — a multi-bot paper-trading system (MT5 FX
books + futures prop-firm simulations). See `README.md` for the stack and
`STRATEGIES.md` for how each strategy works.

## Shared memory: the Obsidian vault

The repo root is also an Obsidian vault. Long-lived project knowledge lives in
`notes/`, so that every assistant (and the human) works from the same context
instead of each chat starting from zero.

| Folder | What goes there | Who writes |
|---|---|---|
| `notes/Home.md` | Start page / map of everything | human, AI on request |
| `notes/Bots.md` | Every bot: config, ledger, log, status | AI keeps it current |
| `notes/Journal/` | One note per day, auto-generated from the ledgers by `scripts/vault_journal.py` | script; humans/AI add observations under the notes marker |
| `notes/Decisions/` | One note per decision that changed live behaviour, with the *why* | AI + human |
| `notes/Experiments/` | Backtests / research: hypothesis, setup, result, verdict | AI + human |
| `notes/Handoffs/` | End-of-session summary so the next assistant can pick up | AI, every session |
| `notes/Inbox/` | Raw material: pasted chats, ideas, links — to be sorted | anyone |
| `notes/Templates/` | Templates for the above | — |

### At the start of a session
1. Read `notes/Home.md` and `notes/Bots.md`.
2. Read the newest 1–2 notes in `notes/Handoffs/` and any open items they list.
3. If the task touches a strategy or risk parameter, check `notes/Decisions/`
   first — don't silently undo a recorded decision.

### At the end of a session that changed something
- Write `notes/Handoffs/YYYY-MM-DD <agent> <short topic>.md` from
  `notes/Templates/Handoff.md` (agent = `claude`, `chatgpt`, `codex`, …).
- If live behaviour changed (strategy, risk, exits, roster), add a note in
  `notes/Decisions/` from `notes/Templates/Decision.md`.
- If a backtest/research result was produced, add a note in
  `notes/Experiments/`.
- Update `notes/Bots.md` if a bot was added, removed, or changed status.

### Note conventions
- Plain Markdown with YAML frontmatter (`type`, `date`, `status`, `tags`).
- Link notes with `[[Note Name]]`; link code/config with normal relative
  paths in backticks, e.g. `config/portfolio_ftmo.yaml`.
- Dates are absolute (`2026-10-03`), never "yesterday".
- Facts and numbers must come from the ledgers, logs or backtest outputs —
  cite the file. Mark guesses as guesses.
- In `notes/Journal/` only write **below** the
  `<!-- notes below are kept on regeneration -->` marker; everything above it
  is regenerated by the script.

### Never put in the vault
- Credentials, `.env` values, account numbers, broker logins, API keys.
